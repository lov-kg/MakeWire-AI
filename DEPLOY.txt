MakerWire AI - Cloudflare Workers source bundle
===============================================

This folder is the full source of the app. Pick ONE deploy route.

------------------------------
Option A - Workers Builds (dashboard, needs Git)
------------------------------

1. Push this folder to a GitHub or GitLab repository.
   (It is not a Git repository yet: run `git init`, commit, add a remote, push.)

2. Cloudflare dashboard -> Workers & Pages -> Create -> Workers -> Connect to Git.

3. Build settings:
     Build command:  npm run build
     Deploy command: npx wrangler deploy
     Root directory: repository root (the folder with wrangler.toml)

4. Deploy. Cloudflare installs dependencies, builds, and uploads.

5. Optional server-side AI keys:
     Worker -> Settings -> Variables and Secrets
       GEMINI_API_KEY  (encrypted secret)
       OPENAI_API_KEY  (encrypted secret)

The `[ai]` Workers AI binding is already declared in wrangler.toml.

`npm run build` runs `theme:generate`, which rewrites
`src/light-theme.generated.css` from the colour utilities used in the source.
Do not hand-edit that generated file.

------------------------------
Option B - Wrangler CLI (no Git needed)
------------------------------

Requires Node.js 20+ (https://nodejs.org).

1. Open PowerShell in this folder.

2. Install dependencies:
     npm.cmd install

3. Sign in once:
     npx.cmd wrangler login

4. Deploy:
     npm.cmd run deploy

`npm run deploy` builds the site, compiles functions/ into .worker/index.js,
and uploads the Worker plus assets.

Validate without uploading:
     npm.cmd run deploy:dry

Optional secrets:
     npx.cmd wrangler secret put GEMINI_API_KEY
     npx.cmd wrangler secret put OPENAI_API_KEY

On macOS/Linux use `npm` and `npx` instead of `npm.cmd` / `npx.cmd`.

------------------------------
Gemini in the app (simple flow)
------------------------------

- Open Settings -> AI & Integrations.
- Paste your Gemini API key.
- Click "Find models" to list the models your key can use.
- Choose one from the dropdown, then click "Test connection".
- A successful test saves the key and the chosen model in that browser.

The chosen model is sent as `x-gemini-model` and used by Test connection and all
AI requests. Temporary Google failures (HTTP 429/500/502/503/504, e.g. "The
model is overloaded") are retried automatically with a short backoff, so a 503
is not treated as a key or model problem. If a test still says "temporarily
unavailable", wait a minute and test again.

If a model is rejected as unavailable, click "Find models" again and pick
another; the Worker also auto-retries with an available model as a safety net.

Inspect a key's models from the command line:
  curl -H "x-gemini-api-key: YOUR_KEY" https://YOUR-WORKER/api/gemini/models

To set a deployment-wide default model, set GEMINI_MODEL in wrangler.toml
[vars] or in the Worker dashboard.

------------------------------
Appearance modes
------------------------------

- Open Settings -> Appearance & Display -> Colour theme.
- Choose Light, Dark, Device automatic, or Day / night.
- Dark is the default, preserving the original look.
- Device automatic follows the operating system light/dark setting live.
- Day / night is light from 07:00 to 19:00 device local time, dark otherwise.
- The value is stored in `makerwire:preferences:v1`. `public/theme-init.js` is
  copied to `dist/theme-init.js` and applies the resolved theme before paint.
  It must remain a same-origin file because the CSP blocks inline scripts.

Theme implementation:
  src/lib/theme.ts                  modes, resolution and watchers
  scripts/generate-light-theme.mjs  generator for light utility overrides
  src/light-theme.generated.css     generated; do not hand-edit

------------------------------
Notes
------------------------------

- The Worker is named makerwire-ai (wrangler.toml). If that name already
  exists in your account, edit `name =` before deploying.
- The first deploy creates https://makerwire-ai.<your-subdomain>.workers.dev.
- An existing Pages project is not modified.
- The app works without AI keys. Settings -> AI & Integrations accepts a
  user-supplied Gemini key, stored only in that browser.
- Never put a Gemini/OpenAI key or a Supabase service-role key in the source.
